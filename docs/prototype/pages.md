# Web 原型：页面与交互

`prototype/` 是同一套 320×240 设计的纯静态可点击原型，用来在接固件之前评审界面。
地图也保留原设备尺寸、顶部导航与底栏，不另设屏幕比例或屏幕外操作区。
无构建、无前端框架依赖、无外部 API 请求、无持久化；图鉴使用示例数据，记录页提供自写剧情梗概，
装备元数据从本地归档生成。

启动命令与服务根要求统一见 [原型本地预览](../../prototype/README.md#本地预览)。

> 本节“示例数据”等表述与原型入口说明存在差异，涉及相应功能时需按 [R3](../context/RISKS.md#r3) 核对当前源码；本轮未据此改写功能结论。

## 本轮原型调整

2026-10-29：网页保留 320×240 逻辑画布，取消 2.2 倍显示上限，按窗口可用空间等比放大。
目录中英文共用 `data.js` 的 ROUTES 父子结构、编号和顺序，只切换文字；覆盖装备、九项能力、图鉴、日志及相册子菜单。标记当前路由并滚动到可见处，保留外部语言切换按钮。设备与目录外框顶底对齐，目录内容独立滚动。
撤回新增的视觉样式，恢复原有 Hylia Serif 字体栈、页面配色和控件样式。英文沿用 Hylia Serif，中文统一使用本地思源黑体 Medium；标题、正文与数字变量共用字体栈。中文为贴近 BotW 正文的风格替代，非实机原版字库。语言切换同步文档 lang 属性。
英文模式取消图鉴、日志、相册中重复的中文副标题；152 条任务梗概和地点已补齐英文，直接显示译文。任务数据源及生成规则见 [原型任务数据](../../tools/README.md#原型任务数据)。
九项能力行为以 [能力演示](trials.md) 为准，下文旧的五关描述不再适用于 HTML 原型。
外部按键使用指针捕获，方向键按下及 OK 长按反馈与键盘同步；取消指针或窗口失焦时停止输入。
普通页面 OK 长按 650 ms 返回上一层，方向键按住 380 ms 后连发。符文中 OK 执行当前动作；制冰/摩托/amiibo/感应器已改为每次单键输入，不要求同时按键，其他场景仍可连续控制方向。长按 OK / Esc 打开暂停菜单，菜单内恢复选择语义。场景失焦或隐藏时自动暂停。

图鉴内容区固定在顶栏与底栏之间，分类列表独立滚动并保留底部统计，避免相对定位偏移导致横向裁切。待机电量改用网上找到的《王国之泪》实机 HUD 截图，以 CSS 取其中一格显示；不再引用生成的电池。待机页增加随语言切换的《旷野之息》中英文标题图，缩小希卡之眼为辅助标记，保留原背景与时钟。标题与电量出处见 [素材来源](../assets/provenance.md#待机标题与电量素材)。

## 输入

- 鼠标点击任意控件；悬停即移动焦点（90 ms 限流）。
- 键盘：`↑`/`↓` 移动焦点，`Enter` 确认，长按 `Enter` 或 `Esc` 返回；也可直接点屏幕下方 UP/OK/DOWN 三键。
- 键位语义与固件一致：

| 输入 | 含义 |
|---|---|
| UP / DOWN 短按 | 前后选择、当前轴减/增、取景平移 |
| OK 短按 | 确认 / 执行 / 再次敲击（时停蓄力） |
| OK 长按 | 符文场景打开暂停菜单，其余页面返回上一层 |
| UP / DOWN 长按 | 符文场景中连续控制场景，其余页面连续选择控件 |

## 路由（哈希）

`#/standby`、`#/runes`、`#/rune/{bomb,bomb_cube,magnet,stasis,cryonis,camera}`、`#/map`、
`#/inventory/[weapons|shields|armors[/装备ID]]`、`#/compendium/[分类/[条目]]`、`#/log`、
`#/log/{main|side}/{故事ID}`、`#/system`、`#/album[/照片]`。

- 展示数据在 `prototype/js/data.js`：5 个符文、5 类图鉴共 24 条（编号与照片对齐原版图鉴）、
  12 张相册；五个符文场景都能从零操作到 `TRIAL COMPLETE`，可重试。地图原图清单在 `app.js`。
- 顶栏为纯文字导航，不含图标；图鉴入口显示 `COMPENDIUM`，页内完整名称为 `HYRULE COMPENDIUM`。
- 日志包含主线、神庙挑战、迷你挑战三类，分类按钮显示各自条数，含全部 DLC 与联动。每条提供中英文标题、地点及自写梗概，不是游戏日志原文；不显示已移除的清单说明提示。
- 列表分类路由为 `#/log/main`、`#/log/shrine`、`#/log/side`；详情在分类后追加任务 ID。按钮切换同步 URL 与侧栏，详情支持上一条/下一条，首尾禁用越界按钮；返回目录保留当前分类，列表长按返回待机。
- 无效分类回退主线，无效任务 ID 回退该分类首条并修正 URL。长标题与地点在列表省略显示，详情保留全文；三键焦点沿用现有选择规则，分类深链接刷新后仍有效。

## 地图页（03 · MAP，当前默认首屏）

- 一张无 HUD 海拉鲁完整底图，直接显示原始 LocationMarker 中的 177 个命名主要点位，含本体 120 座神庙、15 座塔以及驿站、聚落、商店和其他地标。不是全部克洛格、宝箱或 DLC 神庙点位全集。
- 鼠标/触屏拖动移动地图，点击点位在底部直接显示名称、类别和坐标；拖动时底部跟随视野中心最近地点。没有区域、分类、登记、标记或详情弹层。
- 屏内 −/＋ 放大缩小，支持滚轮，1×～16×；“全图”恢复完整视野。三键为 ▲▼ 切换点位并跟随，OK 循环缩放，长按 OK 返回符文，不需组合按键。
- 中英文共享同一批坐标和顺序；地点名称来自原游戏文本转储。数据维护入口为 `tools/gen_map_places.py`，生成 `prototype/js/map-data.js`。
- 感应器完成后仍可直接定位地图中的纳米卡·奥兹神庙；相册不扩展。当前仅静态检查，待用户查看。

## 装备页（01 · EQUIP）

- 8 件武器、4 面盾牌、12 件防具；左侧 5×4 网格、右侧林克立绘与半透明说明卡。
- 移入或 ▲▼ 预览，点击格子或短按 OK 直接装备/卸下，不跳独立详情页；完整说明在右下翻页。
- 武器、盾牌、头部、身体、腿部各占一槽，同槽替换；底部五槽图标，防御合计只累加防具。
- 林克使用 starter 唯一的透明立绘，外观固定，不伪装成动态换装。
- 切分类、翻页、跨页都保留选中位置与装备；刷新/重置清空。数据来自 `assets/data/inventory.json`，
  运行时读 `prototype/js/inventory-data.js`。

## 交互手感

- **选中框**：覆盖层 `.focus-frame`（1px 暖白边 + 四角三角 + 内嵌青边），坐标按
  `(元素 rect − 屏幕 rect) ÷ --scale` 换算，缩放后仍贴合；换焦点整块 0.1s 平移并弹一下。
- **音效**：菜单移动/返回用 `assets/audio/prototype/select.mp3`，确认/装备/入口激活用 `action.mp3`，
  从 starter 归档逐字节导出，不变调；玩法音效原为 `gen_synth.py` 合成的 wav，2026-10-28 已整体移出库
  （见决策 20），当前 `app.js` 里 11 处 `.wav` 请求会 404 静音；音量跟随 SYSTEM 页档位。
- **换页**：路由变化叠一层扫光 `.wipe`；从符文列表进入场景再叠 `.boot-flash`。
- **长按**：按住 OK 650 ms 返回，键底有进度条；方向键按住 380 ms 后每 96 ms 连发一格。
- **提示**：不满足前置的按钮统一置灰；需要解释时用底部 `.toast`（警告金色、1.7 s 消失）。
- **相机 → 相册**：快门写入 `state.albumShots`，相册页与计数同步，新照片带 `NEW` 角标，
  拍完自动切到下一个未登记目标；取景页有三分构图线、中心准星与 REC/F 值 HUD。

## UI 参考仓库

| 仓库 | 取用 | 落到哪里 |
|---|---|---|
| `react-sheikah-ui` | 只借设计语言，未复制代码 | 按钮「内嵌 1px 边 + 四角三角」→ `.focus-frame`；卡片「距外框 2px 再画一圈」→ `.detail-card::before` / `.entry-art::before`；Toast 滑入方向与状态色 |
| `zelda-botw-starter` | Calamity HUD 字体、24 件装备图/数据、林克立绘、7 个 SVG、2 段菜单音效 | 字体 → `prototype/fonts/`，音效 → `assets/audio/prototype/`；双栏布局适配 320×240，不引入 React |

当前英文使用 Hylia Serif，所有可排版中文共用本地思源黑体 Medium，包含侧栏、菜单、日志、图鉴、装备与符文玩法；图片内嵌文字不受 CSS 控制。原件直接从 `assets/raw/07_fonts/` 加载，来源与许可见 [中文字体](../assets/provenance.md#中文字体)。原型字体选择与固件 Flash 预算分开处理。

原型只用于交互与排版评审，不含真实传感器、存储、音频解码或性能约束验证。
