# 原型能力演示与固件试炼

## HTML 原型：九个入口

2026-10-29 更新：原型以 Switch《旷野之息》的能力表现为参考，适配 320×240 与三键，不要求每项能力通关；不受现有固件实现约束。
九项均由 `abilities.js` 分派至统一输入/暂停入口 `prototype/js/rune-games.js`。圆弹、磁力、时停逻辑保留在该文件，其余六项在 `prototype/js/rune-extras.js`。相册重构按用户要求延后，新相机仅临时预览，不写入相册或原图鉴登记状态。

- 圆形炸弹：▲ 减少投掷力度、▼ 增加，OK 抛出；弹体受重力下落、碰地反弹并沿坡滚动，再按 OK 引爆。爆炸中心接近右侧岩石才成功，过早引爆会落空，冷却后可再投；滚出边界失败。OK 可重新挑战。
- 磁力抓取：铁板搭桥。OK 抓取后缓慢抬升，▲▼ 调整当前轴；再次 OK 打开磁力操作菜单，可反复切换水平、升降、放下或继续调整。未对齐时菜单默认另一轴，对齐后默认放下，减少按键次数。菜单打开时暂停物理更新。铁板宽度 148、桥台内侧 112/208、表面高度 128、板底偏移 11 与最小支撑重叠 8 共用几何定义；释放时按板底穿越台面判定落稳，两端各有足够重叠才稳定。桥台分别亮起提示支撑对齐状态，落稳后林克通过；失去支撑则坠落，可重试。场景与物件现按用户新要求统一使用参考实机生成的 v2 图集。
- 静止器：石头沿地面滚动，贴图按位移转动；OK 锁住当时的位置和转角。▲▼ 调整发射角度，OK 击打最多六次，箭头随蓄力变长，满蓄力变为橙色。十秒后自动解除，六次后再次 OK 或点击提前解除可主动释放。释放速度随击打次数非线性增长，镜头横纵向跟随飞行，显示距离刻度与最终飞行/落地滑行距离；六次蓄力远射后完成。这里的距离单位为原型演示比例，不是原作物理实测值。
- 方形炸弹：▲▼ 连续选择落点，OK 放置/引爆。落点对准移动平台时方弹跟随平台，不在平台上则停留地面；需要平台将炸弹运到高处岩石附近才可有效引爆，失误后冷却可重试。
- 制冰器：改为五个固定落点的三步解谜，▲▼ 每次按下切换一处，OK 造冰/碎冰。造满三根自动尝试通过；间距不当或未顶起闸门则失败，按 OK 保留现有冰柱进入调整。无需持续移动光标或打开菜单启动通行。
- 照相机：▲▼ 平移取景，OK 快门。五个目标持续轻微移动，识别依据完整入框、成像大小及岩石遮挡；缩放从屏内按钮或暂停菜单进入，支持 0.75×/1×/1.5×。快门只产生临时识别预览，返回后继续取景；不保存照片、不操作相册，也不调用旧拍照登记流。本次识别蓝夜光草后，感应器可解锁它作为追踪示例。
- 大师摩托 Zero：自动侧视骑行，OK 开始/跳跃，▲ 也可跳跃，▼ 单次短暂减速后自动恢复巡航。不再要求持续加速，也不设燃料阻塞；保持两处沟壑、岩石和终点的时机挑战，只用 OK 也能完成。
- amiibo：▲▼ 单次切换角色，OK 直接读取；落点和走近宝箱自动完成。等补给落地后，OK 开箱，再按 OK 收取，之后可再次体验。不再要求选择落点或操纵人物；奖励仍为原型示例，不声称真实掉落表。
- 希卡感应器：改为岔路寻踪。▲▼ 每次切换左路/直行/右路，先比较所选路线的信号与提示音，OK 自动走到下一岔口并停下；重复直到发现目标。无需同时转向与行走，也不显示精确距离；保留已识别蓝夜光草的可选追踪模式。


### 四项动画与判定修正（2026-10-29）

- 制冰：冰柱从水面升起后才通行，按脚底接触点计算岸边/柱顶位置；每跳包含预备、起跳、落地缓冲。距离过大或门未开时播放安全退回，再进入调整，不再直接切换错误站姿高度。
- 摩托：按统一轮轴、轮半径与石头近似圆形判定，而非车身中心的固定高度阈值；轮子落地锚点和显示同步。按用户要求石头由 30 缩至 20 逻辑像素，碰撞半径由 11 缩至 7，贴地偏移同步改为 9。加入跳跃输入缓冲、离岸短暂容错、提前跳跃提示，以及撞击/落水过渡再失败。此为近似几何判定，不是像素碰撞或实机参数。
- amiibo：读取→重力落下→落地缓冲→等待确认→自动走近→开箱双姿态过渡→奖励揭晓→收取飞入背包。闭/开箱图以共同地面锚点对齐，动画期间阻止重复确认；阶段消息及时更新。
- 感应器：发现后先进入约 3.2 秒显现过程，收起选路、信号和追踪控件，镜头渐近、光环展开、发现标题渐显，结束后保留发现结果并允许再次探索。

以上动画由玩法时间推进，暂停、失焦与隐藏时一起停止。仍仅做静态检查，视觉与操作需用户逐项确认。

九项体验使用统一的 requestAnimationFrame 时间步长更新，画面仍为 320×240。制冰/摩托/amiibo/感应器为逐次单键输入，按下即响应一次，不依赖按住或组合按键；其余场景保留连续方向输入。场景内长按 OK / Esc 打开暂停菜单（继续 / 重新开始 / 返回符文）。暂停、页面失焦、隐藏及离页停止当前玩法时间和方向输入；离页后再进入保留为暂停状态。菜单内恢复普通三键选择。
这些是参考原作机制的独立二维小关卡，并不宣称复刻 Switch 的完整物理、场景或数值。

所有演示提供重置或返回入口。按用户最新要求，九项场景和主要动态物件改用 v2 图集，来源与格位见 [素材来源](../assets/provenance.md#九项符文场景与透明物件-v2)，渲染映射为 `prototype/js/rune-art.js`。感应器以生成神庙场景为主体，接近时逐步增强亮度及景别，不再将菜单图标贴作神庙。amiibo 使用开/关宝箱与透明补给物件，落点和走近过程自动完成；相机需稳定取景约 0.7 秒完成对焦后才算识别。原文件保留，不覆盖其他页面素材。图集是参考生成，不冒称实机截图或原作提取。
本轮仅静态语法与差异检查，玩法、排版和手感待用户逐页验收。

## 固件侧常量

`STASIS_MS=10000`、`STASIS_COOLDOWN_MS=10000`、`STASIS_MAX_HITS=6`、`BOMB_COOLDOWN_MS=2500`、
`ICE_COOLDOWN_MS=800`、`GAME_MAX_STEP_MS=100`、`PHOTO_CAPACITY=8`、`SUBJECT_COUNT=5`。
实现在 `firmware/main/game/`（`bomb/magnet/stasis/cryonis/camera` 各自独立，统一走
`game_init/game_input/game_step/game_reset`，相机另有 `camera_snapshot`）。

## 图鉴与相册

- 图鉴只有**拍照才解锁**：`progress_add_photo` 返回 fresh 才发「发现」事件，未登记条目显示 `?`。
- 图鉴分五类，每类收录 5 条示例（宝物 4 条），编号与照片对齐原版图鉴；
  分类进度显示游戏真实总数（生物 83 + 怪物 81 + 材料 36 + 装备 185 + 宝物 4 = 389）。
- 相册容量 8 张（`PHOTO_CAPACITY`），满后快门提示先删除；新照片带 `NEW` 角标。
- 五个目标全部登记后 `game_complete`，记录页对应条目打勾。

## 进度存储

`firmware/main/game/progress.c` 用带版本号与 FNV 校验的编码写入 NVS（命名空间 `slate_v2`），
提交点是「试炼通关 / 设置保存 / 设置页退出」；`store.c` 只负责读写，不解释语义。
